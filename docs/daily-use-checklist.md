# One week of daily use

Use this checklist after the isolated candidate passes the quality checks and
packaged smoke test. Installation into your daily-use folder is a separate step;
the development build does not replace it automatically.

Before switching versions, exit the app normally and back up
`%LOCALAPPDATA%\Organizador`. Keep your existing installation available. Use
copies of coursework for any intentional interruption tests.

## Once before starting

- Organize a PDF, Office document, and text file; verify their contents and names.
- Search for known text; edit a document and use Reindexar to check the change.
- Return one file and undo another filing. Confirm the files are intact.
- During a slow transfer, try saving settings and requesting an update: both
  should explain that file operations must finish first.
- Quit during a transfer: the closing indicator should remain responsive until
  all accepted operations finish. Do not force-close it during normal use.

## Each day for seven days

Record only concrete friction, without copying private document contents:

- Date and action attempted.
- Expected result and what happened.
- Incorrect subject/type suggestions or filename corrections.
- Search terms that failed to find a document known to be indexed.
- Interruptive prompts, duplicate notifications, or unnecessary clicks.
- Any recovery warnings, with the local log timestamp if available.

Keep these notes locally. No telemetry or automatic upload is needed.

## At the end of the week

Group repeated problems and count how often each occurred. Address any file
safety failure first, then the most frequent workflow friction. Choose the next
retrieval improvement from this evidence; do not treat a clean test suite as a
substitute for the week of use.
